ChatGPT data donation: two participant flows

These pages show what a participant would see in two open-source data donation tools, Port and DDM, each set up to read ChatGPT exports. Study texts are placeholders written as [things to be filled: ...]. Everything runs in your browser.

1. Download a test file

A synthetic ChatGPT export with made-up conversations (no real data): synthetic_chatgpt_export_sharded.zip (the newer layout, conversations-000.json) or synthetic_chatgpt_export_legacy.zip (the older layout, conversations.json). Keep it zipped.

A real export from ChatGPT (Settings → Data controls → Export data) also works. It is read inside this browser tab and is not uploaded.

2. Try each flow

Port

By the D3I project and Eyra (Netherlands). In a study it runs inside Eyra's Next platform.

  1. Study page and consent (in a real study this page comes from Next)
  2. Select the ZIP; a Python script runs in your browser and extracts the messages
  3. Review table: search it, delete rows, then choose to share or not
  4. End page, followed by the payload the server would have received
Open the Port demo

DDM (Data Donation Module)

By the University of Zurich. One application: consent, upload, questionnaire, researcher interface.

  1. Briefing page with a consent question
  2. Select the ZIP; DDM's configured rules extract the messages in your browser
  3. Review, grouped by conversation: remove single messages or whole conversations
  4. Short questionnaire, which can quote the donation (here: the number of messages)
  5. End page, followed by the payload the server would have received

Researcher side: DDM's own researcher interface for this project, as a read-only snapshot with two synthetic participants. Settings, extraction rules and questionnaire can be opened but not saved; the two Data Center downloads work. "DDM back end" shows what DDM stores (encrypted) and what a researcher downloads, in the interface and through its API.

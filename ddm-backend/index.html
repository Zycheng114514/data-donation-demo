DDM back end: what is stored and how researchers get it

Two synthetic participants went through the DDM participant flow of this project: P001 donated all 15 messages of the newer export; P002 removed one conversation from the older export and donated 11 messages. Both answered the questionnaire. This page shows what DDM kept and the three ways a researcher gets it. 1 further internal test participant, used to build the demo pages, is left out of every table and file below.

How DDM encrypts (from its source, ddm/encryption/models.py): each record gets a new random 16-byte AES key; the record is encrypted with it, and the AES key is encrypted with the project's RSA-2048 public key. The stored text is the base64 of both. The matching private key is computed from the server's secret key and a per-project salt, so the database file alone cannot be read, while the running server, or anyone holding the secret key, can decrypt. A project can instead use its own password that the server never stores; then the API below cannot be used and question texts cannot quote the donation.

3. Remote access through the API

Under "Remote Data Access" a researcher creates a token for the project (valid for at most 90 days). A program sends it with every request: Authorization: Token <your token>. The three read endpoints:

requestreturnssaved response
GET /api/project/8MpkNX34/overviewparticipants, the extraction configuration, project settingsapi-overview.json
GET /api/project/8MpkNX34/donations?participants=ID1,ID2the decrypted donations of the listed participants (the list is required)api-donations.json
GET /api/project/8MpkNX34/responsesquestionnaire answersapi-responses.json

The API also has endpoints that delete one participant or all data of a project; they are not called here. A program that processes donations elsewhere would use the donations endpoint to fetch new ones.

4. Not part of DDM

Backups of the database and of the secret key, and anything that happens to the data after download (de-identification, feature extraction, access tiers, deletion schedules) are outside DDM.
